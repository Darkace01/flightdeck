## New

- **Deployments dashboard, Octopus Deploy style.** See what's deployed where, straight from the deployments GitHub records whenever an Actions job with an `environment:` runs. Your workflows need no changes. Add the **Deployments** widget, start a dashboard from the new **Deployments** template, or open a repo's **Deployments** section. There are three views:
  - **Environments:** projects down the side, environments from dev to prod across the top. Each cell shows the live release (its tag, or the commit if it isn't tagged), how long ago and who deployed it. A newer failed or in-progress attempt shows beneath it.
  - **Clients:** environment names are split into a stage and a client, so `prod-acme`, `staging-acme` and `Acme` all count as the client *Acme*, and `dev` or `Production` are shared stages. Each client gets a row with its version at every stage.
  - **History:** every deployment, newest first, with its environment, client, version, outcome, duration and who ran it. Filter by environment, outcome or text.
  - Click any deployment to open the workflow run that made it.
- **See where a run deployed.** In the Runs widget, deploy runs carry a label with their target environment (for example **⇢ prod-acme**). A run's details list each environment and client it deployed to, with the version and outcome.
- **Pull requests and issues open in a side panel.** They slide in from the right instead of opening as a pop-up. A rail on the left of the panel shows:
  - the repo's details and CI status
  - what's live in each environment
  - the repo's other open PRs, so you can switch between them without closing the panel
