## New

- **Notification rules.** Settings → Notifications can now snooze notifications for an hour or until tomorrow morning, set quiet hours (a daily window that can cross midnight), and mute individual repos. These only hold back the pop-ups: everything still appears in Activity and in the unread count.

- **Review pull requests without leaving Pushback.** A new **Review…** button on a pull request lets you comment, approve or request changes, with a message (required for comments and change requests). **Merge…** can now turn on auto-merge, so GitHub merges the pull request for you once its checks and reviews pass. Inline comments on specific lines still need GitHub.

- **See what blocks a pull request from merging.** A new panel on the pull request view lists the required checks, approvals against the branch rule, conflicts, unresolved conversations, auto-merge and the pull request's position in the merge queue. When GitHub says a pull request is blocked but doesn't say why (a repository ruleset), Pushback says so instead of showing it as clear.

- **Security alerts widget.** Dependabot, code scanning and secret scanning alerts in one list, filterable by source and severity, plus the open Dependabot pull requests.

- **Packages widget.** See the GitHub Packages (npm, container, NuGet, Maven, RubyGems) you have published, or switch to organisation level to see what your organisations publish, either for one org or all of yours. Open a package to list its recent versions and image tags. Versions are only requested when you open a package, so the widget stays light on the rate limit. It needs a token with the `read:packages` scope and says so when it is missing.

- **CI health widget.** Failure rates, flaky workflows, the slowest workflows and an estimate of Actions minutes, over the last 14 days by default. It is worked out from the runs Pushback already fetches, so it adds no requests. A commit that both failed and passed, or passed only on a retry, counts as flaky. Minutes are wall-clock estimates, not billing figures. There is also a CI health section in each repo's tab and a row in the CI monitor template.

- **Clean up old branches and pull requests.** A new section in each repo's tab lists merged branches, stale branches with unmerged commits and old open pull requests. Merged branches are ticked and the rest are not, and you see the exact list and confirm before anything is deleted. Pushback re-checks every item just before acting: it never touches the default branch, skips a branch that has gained an open pull request, and reports each failure instead of stopping.

- **Several accounts and GitHub Enterprise Server.** Add extra accounts with their own host and token in Settings. Repos can be added by their Enterprise URL, links open on the right host, and local clones link and clone against it. Tokens are stored encrypted, each server only ever sees its own token, and your github.com login stays the primary account for the inbox.

- **Saved searches.** Pin any GitHub issue or pull request search, such as `is:open author:@me`, as a dashboard widget that runs across every org. Filter by repo, author, label and drafts without extra requests. Searches refresh when you open the widget and every 3 minutes while it stays open.

- **Share dashboards and templates.** Manage dashboards now has **Share** (copy a small piece of text or save a file) and **Import** (paste it or open a file). A shared dashboard is added next to your own, and Pushback never takes folder paths from it.

- **Draft release notes from merged pull requests.** The new release dialog has a button that lists the pull requests merged since the last release, grouped by label or commit prefix, and fills the notes box so you can edit them. Releases now start as drafts; publishing still needs the draft box unticked.

- **Launch at sign-in.** Settings has "start when I sign in" and "start in the tray". They only take effect in the installed app.

## Improved

- **Running a workflow takes you to the run it started.** Instead of dropping you back on the dashboard, Pushback finds the run it just queued and opens it, so you can watch its jobs and logs. If the run doesn't show up within about 12 seconds you get the usual "Started" message.

- **The tray badge counts what needs you.** Besides unread activity it now counts review requests and your own pull requests that are failing or have changes requested, without counting anything twice.

- **Importing settings keeps this computer's accounts and linked folders,** and a settings file exported from here no longer includes your folder paths.

## Fixed

- **Dashboard tabs no longer slide under the search box** when you have many dashboards or a narrow window. The tabs now shrink to fit, the search box shrinks before they do, and at least one tab and the overflow menu always stay visible.

- **Test runs no longer collide with a Pushback that is already open.**
